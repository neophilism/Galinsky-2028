# Configurable hero backgrounds — implementation PR plan

Owner directive: hero backgrounds must be independently configurable for each database-backed campaign and (optionally) separately for day and night. This is part of the existing editorial content manager, not a second content system. **No specific editorial campaign names, messages, or owners' uploaded art belong in source control, commits, PRs, logs, CI artifacts, or fixtures.**

## Result and presets

The protected admin hero panel must edit the image, image description, focal point, **background effect**, animation toggle, intensity, opacity, blur/softness, speed and appearance override in one place. It must preview the result at desktop/mobile sizes and allow seeing it in the full unpublished page preview without publishing.

Supported presets, with stable machine IDs and descriptive labels: **Clean** (`none`), **Ethereal Cloud Drift** (`clouds`), **Soft Aurora Veil** (`aurora`), **Radial Glow Halo** (`halo`), **Silk Wave** (`silk`), **Atmospheric Grain and Light Beams** (`beams`), **Geometric Glow Field** (`geometry`), and **Particle Field (Legacy)** (`legacy`). Use `aurora` as the initial default in the new system; preserve the original particle animation only when explicitly selected. Effects use existing database theme colors and the selected background. A dark appearance's neutral mist uses its selected dark surface/background, not a hard-coded white wash.

The default effect belongs to each campaign document. Optional day and night overrides can inherit that default or specify their own complete settings. The global day/night campaign assignment still picks which entire published campaign renders first; then that campaign's effect override resolves for the chosen appearance. A disabled global appearance feature always resolves the campaign's default effect, regardless of saved day/night overrides.

Stored data: optional `heroBackground: {default: EffectSettings, day: EffectSettings|null, night: EffectSettings|null}` on the existing immutable campaign revision JSON. Existing records without this property remain readable and resolve a safe default. `EffectSettings` contains `preset`, `animated`, `intensity`, `opacity`, `blur`, `speed`. Strict allowlists and numeric bounds prevent CSS and HTML injection; no freeform CSS, image URL or remote code input. Publication pins text, hero image, colors and effect as one revision. No SQL schema migration is necessary because the existing content record uses JSONB; tests verify old and new records.

## Delivery PRs (or independently reviewable commits in one PR)

1. **Contracts and plan.** Add pure validation/resolution utilities, preset descriptors/defaults and generic tests. Prove stored and projected values round-trip, unknown keys/styles and NaN reject, and old documents without effects remain valid. No changes to existing financial/security contracts.
2. **Shared visual renderer.** Replace the original canvas only for database-driven published pages, using a non-interactive, decorative effect layer. Add reusable CSS-based effects driven by colors in each campaign's theme. Respect disabled animation, `prefers-reduced-motion`, document visibility and offscreen pause. Keep the legacy particle canvas only for the explicit legacy choice. Avoid third-party libraries, network calls, WebGL, user tracking, autoplay audio and layout shifts. Test mode overrides, escaping/CSS boundaries, head metadata consistency and DOM structure.
3. **Single-place admin controls.** Add preset selector, default/day/night override selector, inherit-default action, animation toggle, intensity/opacity/blur/speed controls and live previews to the existing protected hero-image editor. Preserve all text, image, colors, single-campaign, side-by-side and unpublished preview functions. Preview must never mutate a published revision; stale saves still return 409. No new editorial endpoint or privilege is necessary.
4. **Cross-browser, security, performance and rollout.** Unit/API/real database/template/browser tests (Chromium/Firefox/WebKit); mobile 320px and reduced motion; day/night same/different campaigns; malformed settings; no-JS static appearance; visibility/offscreen pause; absence of particles for new presets; existing portrait/text readable above effects; no network or CPU-intensive background loops. Confirm full existing CI green before merge. Deployment, any live theme switch, and any content publication are separate controlled steps in the existing password-protected Render/Neon setup.

## Acceptance and non-goals

A campaign owner can create an arbitrary new campaign, select a background, change the hero and palette, save, reload, preview, publish, and separately assign any two published campaigns day/night. Inherited/overridden presets and parameters must render identically in preview and live site. Switching appearance must change all content from one revision together. No effect may cover headline, buttons or portrait, break keyboard focus, obscure contrast, or cause horizontal overflow. Animated effects stop or freeze when reduced motion is requested, offscreen, or document hidden. Static gradients remain visible even without JavaScript. Use ordinary CSS/compositor animation; never ship unbounded per-frame canvas loops for nonlegacy presets.

Do not alter protected legal/financial/volunteer strings or their runtime authorizations. Do not publish actual editorial draft content as part of these code PRs. The current private preview and database release flags stay unchanged until tested authorization and owner publication. Evidence must separate coded, tested, merged, deployed, and live-verified status. Preserve canonical existing work units and registers; the relevant content/editor/visual scope can be assigned to its existing units rather than inventing a competing progress registry.
