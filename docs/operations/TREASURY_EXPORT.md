# Controlled ledger review exports

Owner and treasurer roles can download CSV/JSON review exports from Treasury administration after fresh passkey verification, CSRF validation and explicit confirmation. Auditors, ordinary administrators and volunteers cannot bulk-extract financial data. The request accepts only a UTC period of at most 366 days, format and a fixed purpose. It is limited to 10,000 events and three requests per hour. CSV formula/control prefixes, quotes and commas are escaped; source schema, duplicate identity, period bounds and integer cents are validated.

The export reads the signed provider event ledger in a consistent transaction. Captures, refund deltas and disputes have separate per-provider period totals. It includes exact event/payment references and source evidence digests. A SHA-256 manifest and audit event must commit before any bytes leave the service. Audit failure rolls back the manifest and fails the request. Output is private/no-store and is never put in public analytics, GitHub artifacts, mail or a public donor directory. The downloaded file is then the authorized recipient's responsibility; retained copies cannot be remotely erased.

This generic review schema is not a filing submission or proof of deposit reconciliation. Period movements are not opening/closing balances. It does not export bank credentials, private volunteer reports or fabricated donor fields. Actual accounting/FEC mapping, donor/source reports and authorized retention remain tied to the selected treasury workflow. The treasurer must identify that system and approve the real mapping before a production import. No automatic filing, live charge or refund is initiated.

Apply migration `020_treasury_exports` before using this feature. Golden-schema/totals/injection tests and actual HTTP/PostgreSQL tests cover roles, stale MFA, CSRF, exact byte digests and transaction rollback on audit failure. Fixtures use synthetic records in isolated local PostgreSQL, never the assigned campaign database.
