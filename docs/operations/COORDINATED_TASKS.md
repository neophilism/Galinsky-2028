# Coordinated tasks, training and approved tools

The verified staff workspace at `/assignments-admin` manages versioned task, training and approved-tool definitions. Owner/coordinator grants require a fresh staff passkey. Captains can review only tasks that explicitly list their volunteer references; financial/security roles do not gain task management. Training verification requires a different authorized trainer, exact current training revision, source evidence digest and bounded expiry. No seeded definition pretends an actual campaign review or authorization occurred.

Tasks pin an approved material revision, one of twelve roles, instructions, stop conditions, estimated time, availability, capacity, training and, for restricted tasks, the exact activity-module revision and approved tool. Restricted roles cannot be relabeled as low-risk. Current training definitions must still point at current published volunteer materials. Each claim/report/handoff rechecks current guide, task window, module publication/revision, source-review currency, training attestations and tool review. Advisory/row locks serialize claims, capacity, changed definitions, revoked modules, training records and tool consent. A completed worksheet or self-check does not create a verified training attestation.

The volunteer `/tasks` page retains its existing first-hour checklist and adds coordinated assignments when the staff identity/database release is configured. Claims, release and aggregate reports persist across sessions. Reports accept bounded count/minutes and a fixed feedback choice, with explicit signed-in/self-reported provenance. They accept no free-text supporter fields. Independent scoped staff review marks a result verified or rejected; a person cannot verify their own result. Immutable claim history and redacted audits retain transitions; account foreign keys support eventual lifecycle cleanup. Completed exclusive assignments consume their original capacity; releasing/rejecting a place permits another claim. Leaving remains possible after a module is paused.

Tool definitions contain a stable HTTPS destination, purpose, source-bound review digest and expiry. New tool revisions require renewed explicit participant consent. Opt-out stops future server-authorized handoffs immediately. Tool opening requires a current claimed task and all current activity gates, and audits the handoff without sending account/report/supporter data in the URL. This is a controlled link integration, not authority to create external accounts, send messages, export records or revoke copies already retained by an external service. Those providers' account/deletion/incident procedures remain their own obligations. No scraped contact list, mass texting, autodialing or sensitive export is introduced.

Apply migration `019_operations` with the other reviewed migrations before enabling the staff identity release. Publish actual reviewed material, training, tools and activity requirements using existing staff authority. Existing API credentials are reused. Real tool contracts/content and actual training verification are configuration/operations evidence; do not invent them from generic test fixtures.

The isolated PostgreSQL HTTP test covers simultaneous last-place claims, stale definitions, rejection of supporter fields, independent/scoped report verification, expired/revoked prerequisites, current training, tool consent withdrawal and MFA. The browser suite uses the actual app and isolated PostgreSQL across Chromium, Firefox and WebKit to create an assignment, claim/report it, verify it from a different account, reload persistence and check mobile reflow. CI uses synthetic accounts and never sends real email or opens a real operational tool.
