# Staff identity and step-up verification

Staff email login is paired with WebAuthn passkeys using pinned SimpleWebAuthn server/browser libraries. Set `STAFF_IDENTITY_ENABLED=true` only after migration `016_staff_passkeys.sql` and normal verified-email owner login are configured on the existing portal. No new identity-provider account or API key is needed. Keep preview protection and financial activation controls in place.

Staff visit `/security` after email sign-in. The first passkey must be registered within ten minutes of a new email login; further passkeys require a fresh existing-passkey verification. The browser and server require authenticator user verification. Server validation binds each one-use, five-minute challenge to the exact account, session, configured origin and relying-party hostname. Registration and authentication use the maintained verifier, not caller-supplied identity assertions. Public keys are stored; authenticator private keys never reach the server.

Successful verification grants fifteen minutes of staff access to that existing session. Treasury, operational administration, campaign editing and owner coordination check fresh session/role/device authority. Revoking a passkey ends every step-up session made with that key. Role revocation and ordinary session expiry remain authoritative. Enroll another passkey for recovery. Losing all keys requires a new verified email login before enrollment; this recovery boundary does not claim hardware-only account recovery or recipient-key restoration.

PostgreSQL serializes per-account security transitions with an account row lock. Challenges are consumed in a committed transaction before proof verification, including invalid proofs. Normal account deletion cascades security records. No credential bodies or authenticator proof are written to logs or returned in administration lists.

`tests/staff-security.test.mjs` constructs genuine ES256/COSE registration and signed assertions and runs the real verifier through HTTP. It tests origin, user verification, consumed challenges, replay counters, CSRF, expiry, revocation and fresh-mail recovery. `tests/integration/staff-security.test.mjs` verifies actual PostgreSQL persistence, concurrent updates, cross-session revocation and account cleanup. These are automated integration evidence; they are not a claim that the owner's physical authenticator has been enrolled on the hosted portal.
